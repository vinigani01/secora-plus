# SECORA - Secure ESG and Cyber Operations Risk Analyzer

SECORA scores companies with two independent Isolation Forests (ESG and cyber), merges them with a
power mean into one 0-100 risk score, and records every score in a SHA-256 hash-chained audit ledger.

## How it works

| Piece | Detail |
|---|---|
| ESG features (9) | 3 pillar scores, industry-normalised composite (z within sector), YoY change, emissions intensity (emissions / revenue), expenditure share (ESG spend / revenue), sector-relative position (composite minus sector median), score consistency (composite minus mean of pillars) |
| Cyber features (6) | incident count, breach count, average severity, mean days to detect, log10 records exposed, critical vulnerabilities (company-level; swap in CICIDS2017 flow statistics by editing `CYBER_FEATURES` and `build_cyber_features`) |
| Detectors | One `StandardScaler` + `IsolationForest(n_estimators=200, contamination=0.15)` per domain, trained and stored separately |
| Domain score | `-score_samples` calibrated to [0, 1]: training median maps to 0, training 99.5th percentile to 1 |
| Aggregate | `R = (0.5·sE³ + 0.5·sC³)^(1/3)`, x100. Bands: LOW < 25, MEDIUM < 45, HIGH < 65, CRITICAL >= 65 (edit `RISK_BANDS` in `config.py`) |
| Explanations | Per-feature z-scores from each domain's scaler, sorted by magnitude |
| Model manifest | `models/manifest.json` records features, parameters, calibration and the SHA-256 of each model file. Models refuse to load if a file does not match. `mh` = SHA-256 of the canonical manifest JSON |
| Ledger | One record per company per run: `tau = <t, R, sE, sC, rid, mh>`, `h = SHA256(CanonicalJSON(tau) ‖ h_prev)`, genesis `h_prev = 64 zeros`. `rid` is `<run id>-<n>` and links the record to its `anomaly_results` row |
| Fallback | If scoring fails (model missing/tampered, DB error), `/api/analyze` returns HTTP 200 with `status: "fallback"` and the committed `fallback_results.json`; `/api/dashboard` and `/api/results` do the same when no completed run exists. The UI shows a "stale results" banner |

CSV schema for `/api/upload` (header names are case-insensitive):
`company, sector, environmental_score, social_score, governance_score, composite_score, emissions (tCO2e), revenue (USD m), esg_expenditure (USD m), incident_count, breach_count, avg_severity (0-10), mttd_days, records_exposed, critical_vulns` plus optional `ticker, prior_composite_score`. Scores must be 0-100, at least 20 rows, unique company names.

## 1. Run locally with Docker

```bash
docker compose up --build
```
- UI: http://localhost:3000  - API docs: http://localhost:8000/docs
- The backend image trains the models during `docker build`, so it starts ready.
- Click **Load demo data**, then explore the three tabs. Quick API check:
  ```bash
  curl -X POST localhost:8000/api/demo
  curl -X POST localhost:8000/api/analyze -H 'content-type: application/json' -d '{}'
  curl localhost:8000/api/blockchain/verify
  ```
- Reset everything: `docker compose down -v`.

## 2. Scrape data and train

Run these from `backend/` (Python 3.12):
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-scraper.txt

python -m scripts.scrape_data --max-esg 120   # writes data/training_companies.csv
python -m scripts.train                       # writes models/*.joblib, manifest.json, data/fallback_results.json
```
What the scraper really collects: the S&P 500 universe and sectors and a breach history from Wikipedia (BeautifulSoup), plus
best-effort Yahoo Finance ESG scores and revenue through `yfinance` for the first `--max-esg` tickers (Yahoo may return nothing
for many tickers, and its page layout changes). Per-company emissions, ESG spend and operational cyber metrics are not freely
available, so missing values are imputed from the seeded generator and flagged by `esg_real` / `breach_real` in the CSV.
Check the scraped sites' terms of use before running it at scale, and treat the imputed columns as synthetic.

`train.py` always adds 600 synthetic companies to the scraped rows. Rebuild the Docker image (`docker compose build backend`)
after retraining so the new models and `fallback_results.json` are baked in. Commit `data/fallback_results.json` and `data/training_companies.csv`.

Without Docker, run the stack by hand: start Postgres (or leave `DATABASE_URL` unset to use SQLite), then
`uvicorn app.main:app --reload` in `backend/` and `npm install && npm run dev` in `frontend/` (the Vite dev server proxies `/api`).

## 3. Deploy to Render

1. Push this repo to GitHub (include `backend/data/fallback_results.json`).
2. In Render: **New > Blueprint**, select the repo. `render.yaml` creates `secora-db` (Postgres), `secora-backend` and `secora-frontend`.
3. After the first deploy, open each service and note its public URL. If Render added a suffix because a name was taken, update:
   - `secora-backend` > Environment > `CORS_ORIGINS` = the frontend URL
   - `secora-frontend` > Environment > `API_BASE_URL` = the backend URL (no trailing slash)
   
   Redeploy both. No rebuild is needed for the frontend: the URL is written into `config.js` when the container starts.
4. Open the frontend URL and click **Load demo data**. Check `https://<backend>/api/health`.

Notes: free web services sleep after inactivity, so the first request can take about a minute. Free Postgres expires after
30 days; pick a paid plan for real use. Backend build time includes model training (under a minute).

## 4. Demonstrate tamper detection

```bash
docker compose exec db psql -U secora -d secora -c "UPDATE blockchain_audit SET risk = 1 WHERE idx = 5;"
curl localhost:8000/api/blockchain/verify    # valid:false, first_invalid_idx:5
```
The Audit trail tab turns red at the broken record. A hash chain cannot detect deletion of the newest records on its own, so
periodically save the `head_hash` from `/api/blockchain/verify` somewhere outside the database (a log, a ticket, a signed commit).

## Limitations

- The demo and initial training data are synthetic; the Isolation Forests flag statistical outliers relative to that
  distribution, not proven ESG misconduct or confirmed cyber incidents. Retrain on your own data before relying on scores.
- Sector features (industry-normalised composite, sector-relative position) are computed within each scored batch, so very
  small sectors fall back to global statistics.
- The ledger is tamper-*evident*, not tamper-proof: anyone with database write access can rewrite the whole chain unless the head hash is anchored externally.
